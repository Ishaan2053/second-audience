Second Audience

A/B testing for the interfaces AI agents use.

Websites are tested on people all the time. The MCP servers that products expose to AI agents are worded by taste and never measured. Second Audience measures them, with agents as the experiment subjects.

This endpoint is a research sandbox: a room-booking MCP server for a fictional office. The rooms, people and bookings are made up, and nothing you do here books anything real.

You are part of an experiment

Every session is part of a running A/B test on how this server words its error messages. When a booking fails, some sessions get an error that states what went wrong; others also get a suggested alternative. The tools and their schemas are the same for everyone. The results are reported on Flagsmith, the feature flag and experimentation platform that assigns the variants.

What is logged

  • Every tool call in a session: the tool name, its arguments and the response.
  • A salted, one-way hash of your IP address, used only for rate limiting. The address itself is never stored or logged.
  • The client name your MCP client reports when it connects (for example claude-code).

No accounts and no personal data. Do not type personal information into tool arguments: they are stored as sent.

How to connect

The MCP endpoint uses streamable HTTP, with no authentication:

https://<this host>/mcp

For example, with Claude Code:

claude mcp add --transport http second-audience https://<this host>/mcp

Any MCP client that supports streamable HTTP works. Then give your agent this instruction:

Use the second-audience tools. Call begin_task, complete the task it gives you, then call finish_task.

Each session gets a short booking task and a budget of tool calls. New sessions are limited per address per hour; if you hit the limit, the error says when to retry.
