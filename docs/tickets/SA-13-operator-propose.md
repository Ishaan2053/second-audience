## 1. Objective

Implement `sa propose`: read sessions that failed or produced wrong bookings, identify the pattern, and draft the next experiment as a spec file with a written rationale for a human to review.

## 2. Context

This is the most agent-like part of the operator and a strong point for Track 02. It shows the loop closing: evidence from the last experiment becomes the hypothesis for the next. It only drafts files. It never creates anything in Flagsmith; that remains `sa start` with typed confirmation. Experiment 1 stays the only running experiment: proposals made during the hackathon are shown, not started.

## 3. Scope

**In scope**

- `sa propose [--from-slug <slug>] [--limit N]`.
- Draft spec at `experiments/proposals/<new-slug>.yaml` and rationale at `experiments/proposals/<new-slug>.md`.
- Validation that the proposed variant is expressible with existing `ErrorStyle` settings.

**Out of scope**

- Starting the proposed experiment.
- New style settings or any server code change.
- Automatic iteration.

## 4. Implementation instructions

- **Evidence pack** built in code from the ledger: counts of outcomes by arm and scenario kind; for up to N sampled non-correct sessions, the compact transcript (tool, arguments, error code, whether the agent followed `corrected_call`, final outcome). Compute a "followed suggestion" flag in code by comparing the call after a styled error with the `corrected_call`.
- **Model step.** Send Gemini the evidence pack, the current `ErrorStyle` settings and their meanings, and the spec schema. Ask for JSON only: an observed pattern, a hypothesis, a variant expressed as an `ErrorStyle` value, the primary metric, and a rationale that cites session IDs from the pack. Use the SDK's structured-output feature if available (check Context7).
- **Validation in code:** the variant parses as `ErrorStyle`; it differs from every arm of the source experiment; cited session IDs exist in the pack; the slug is new. On failure, retry once with the validation error, then exit non-zero with the raw output saved for inspection.
- **Output.** Write the spec with `environment: production`, a 50/50 split against the current best-known arm as control, and a stopping rule copied from the source spec. Write the rationale file with the evidence table (numbers from code), the model's reasoning, and a clear header: "Draft generated by a model. Review and edit before committing."
- The command prints the paths and the next step (`review, commit, then sa start`). It writes an `audit_log` row with action `propose`.
- With no model key, print the evidence pack and exit with a message; do not invent a proposal.
- The expected natural proposal after experiment 1 is prescriptive plus `caution_note`, but do not hard-code it.

## 6. Acceptance criteria

- With a seeded ledger, `sa propose` writes a valid spec and rationale, and the spec passes `ExperimentSpec` validation.
- A model response proposing an unknown setting is rejected and retried once.
- Cited session IDs in the rationale exist in the ledger.
- No Flagsmith call is made by this command (assert with the admin wrapper faked).
- `sa start --dry-run` accepts the generated spec.

## 7. Testing requirements

- Unit tests with a fake model client: happy path, invalid setting, bad citations, no key.
- Unit test for the "followed suggestion" computation.
- Manual: run on the live ledger and judge whether the rationale is sensible.
